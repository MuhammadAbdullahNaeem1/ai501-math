In the first three lectures a matrix was a machine we knew, and we asked what it could produce. Machine learning reverses the situation: we observe examples of inputs and outputs, and we must **find the machine**. The data are still vectors — every patient is a point in $\mathbb{R}^d$, and a dataset is a matrix with one row per patient — and our first learner, $k$-nearest neighbours, uses nothing more than the distances of L01.

In order, this lecture covers: the supervised-learning set-up; loss functions; learning as optimisation, overfitting, and the train/validation/test split; a map of classification methods; the $k$-nearest-neighbour algorithm, including distance metrics, normalisation, the choice of $k$ and its cost; the curse of dimensionality; and the evaluation of classifiers — accuracy and its trap, the confusion matrix and its metrics, trade-offs, ROC curves and AUC, $F$-scores and the Matthews correlation coefficient.

## 1. The supervised learning setup

:::figs
l04-p03|Oxygen-saturation example
:::


:::background functions, pairs and 'drawn from a distribution'
**A function** $h$ takes an input and returns an output. Writing $h:\mathcal X\to\mathcal Y$ means "$h$ takes inputs from the set $\mathcal X$ and returns outputs in the set $\mathcal Y$". For example, a function that takes a patient's 8 measurements and returns a predicted oxygen level is $h:\mathbb{R}^8\to\mathbb{R}$.

**A labelled pair** $(x_i,y_i)$ is one example: the inputs $x_i$ (a feature vector) together with the correct answer $y_i$ (the label). The training set $D$ is just a list of such examples.

**"Drawn from an unknown distribution $P(X,Y)$"** means: there is some real-world process that produces patients and their outcomes, with certain combinations being common and others rare. We never see the full process — only the $n$ examples we happened to collect. The goal is a rule that works for **future** examples from the same process, not just the ones we have.

**The symbol $\times$ between sets** (as in $\mathcal X^d\times\mathcal Y$) means "pairs": the first element from $\mathcal X^d$, the second from $\mathcal Y$.
:::


:::def Training data
$$
D=\{(x_1,y_1),(x_2,y_2),\dots,(x_n,y_n)\}\subseteq\mathcal X^d\times\mathcal Y .
$$
Each $x_i\in\mathcal X^d$ is the **feature vector** of example $i$, a point in a $d$-dimensional **feature space**; each $y_i\in\mathcal Y$ is its **label**, taken from the **label space**.
:::

The label space determines the kind of problem:

| Problem | Label space $\mathcal Y$ |
|---|---|
| **regression** | $\mathcal Y=\mathbb{R}$: a prediction on a continuous scale |
| **binary classification** | $\{0,1\}$, $\{-1,1\}$ or $\{1,2\}$ |
| **$M$-class classification** | $\{1,2,\dots,M\}$ |

In the slide's example, records of $200$ patients — age, cholesterol, glucose, BMI, height, heart rate, calorie intake and number of steps, so $d=8$ and $n=200$ — are fed to a model $h$ that predicts **oxygen saturation**. This is a regression problem.

1. A student's cumulative percentage score: **regression**.
2. A student's letter grade: **classification**.
3. The *probability* that electricity prices fall next year: **regression**, since the output is a number in $[0,1]$.
4. *Whether* electricity prices fall next year: **classification**.

:::

**Learning.** We assume the pairs $(x_i,y_i)$ are drawn from an unknown distribution $P(X,Y)$ — nature's secret question bank, of which we see only the questions we happened to draw. The goal is to learn a function $h$ (also called a model, a machine or a **hypothesis**) such that, for a new pair $(x,y)\sim P$,
$$
h(x)=y\ \text{with high probability (classification)},\qquad\text{or}\qquad h(x)\approx y\ \text{in some optimal sense (regression)}.
$$

:::def Hypothesis class
The **hypothesis class** $\mathcal H$ is the set of candidate functions — for example all linear models, all neural networks of a given architecture, or all decision trees — from which we select $h\in\mathcal H$. The slides answer "how?" in two steps: first define $\mathcal H$ for the problem; then evaluate each candidate and pick the best. The second step requires a way of scoring candidates, which is the **loss function**.
:::

:::remember
Supervised learning combines labelled pairs drawn from an unknown $P(X,Y)$, a chosen family $\mathcal H$, and a loss used to pick the best $h\in\mathcal H$; real-valued labels give regression and categorical labels give classification.
:::

## 2. Loss functions

:::background averages, absolute values and squares
**A loss turns "how wrong" into one number.** For each example, compute the error $e_i=h(x_i)-y_i$ (prediction minus truth). Then summarise all the errors.

**Why not just add the errors?** An error of $+5$ and an error of $-5$ would cancel to $0$, hiding two bad mistakes. So we first make every error non-negative:

- **absolute value** $|e_i|$ — the size of the error, ignoring its sign;
- **square** $e_i^2$ — also non-negative, and it makes large errors count much more ($10^2=100$, but $1^2=1$).

**Why divide by $n$?** It turns a total into an **average per example**, so that a dataset of 200 patients and one of 2 million can be compared on the same scale.

**The $\delta$ in the 0/1 loss** is the Kronecker delta from L01: $\delta_0=1$ and $\delta_k=0$ for $k\neq0$. So $1-\delta_{h(x_i)-y_i}$ is $0$ when the prediction is exactly right and $1$ when it is wrong — it simply counts mistakes.
:::

A loss function $\mathcal L$ measures how badly $h$ predicts $y$ from $x$. Each loss below is **normalised by $n$**, so it is a loss **per sample** and datasets of different sizes can be compared. **All of them are non-negative.**

:::def The 0/1 loss
$$
\mathcal L_{0/1}(h)=\frac1n\sum_{i=1}^n\Big(1-\delta_{\,h(x_i)-y_i}\Big),\qquad\text{where}\quad \delta_k=\begin{cases}1,&k=0,\\0,&\text{otherwise.}\end{cases}
$$
Each term is $1$ for a mistake and $0$ for a correct prediction, so the loss **counts the mistakes** of $h$ on $D$ and divides by $n$. It is **rarely used for training**, because it is neither continuous nor differentiable: its surface is flat almost everywhere, with sudden jumps.
:::

:::def Squared loss (MSE) and its root (RMSE)
$$
\mathcal L_{\mathrm{sq}}(h)=\frac1n\sum_{i=1}^n\big(h(x_i)-y_i\big)^2,
\qquad
\mathcal L_{\mathrm{rms}}(h)=\sqrt{\frac1n\sum_{i=1}^n\big(h(x_i)-y_i\big)^2}.
$$
The penalty grows **quadratically** with the size of each error, so a single error of $10$ costs as much as a hundred errors of $1$. The loss is smooth and easy to optimise, and the RMSE is measured in the **same units** as $y$.
:::

:::def Absolute loss (MAE)
$$
\mathcal L_{\mathrm{abs}}(h)=\frac1n\sum_{i=1}^n\big|h(x_i)-y_i\big| .
$$
The penalty grows **linearly** with the error. The slides note that it is used in regression and is **suited for noisy data**, because a few outliers cannot dominate it.
:::

:::example The three losses on four patients (revision notes)
True saturations $y=(97,94,99,90)$ and predictions $(96,95,99,84)$ give errors $(-1,1,0,-6)$. Then
$$
\text{MSE}=\frac{1+1+0+36}{4}=9.5,\qquad \text{RMSE}=\sqrt{9.5}\approx3.08,\qquad \text{MAE}=\frac{1+1+0+6}{4}=2 .
$$
The fourth patient contributes $36/38\approx95\%$ of the squared loss but only $6/8=75\%$ of the absolute loss.
:::

:::thm The best constant predictor (PSet 4, Problem 5)
If $h(x)=c$ is constant, the squared loss is minimised by the **mean** of the labels and the absolute loss by a **median**.
:::

:::proof
**Squared loss.** Differentiate with respect to $c$ and set the derivative to zero:
$$
\frac{d}{dc}\,\frac1n\sum_{i=1}^n(y_i-c)^2=-\frac2n\sum_{i=1}^n(y_i-c)=0\quad\Longrightarrow\quad c=\bar y .
$$
The second derivative equals $2>0$, so this is a minimum.

**Absolute loss.** The function $\sum_i|y_i-c|$ is not differentiable at the data points, but between them its slope is
$$
\frac{d}{dc}\sum_{i=1}^n|y_i-c|=\#\{i:y_i<c\}-\#\{i:y_i>c\}.
$$
The loss decreases while more points lie above $c$ and increases once more lie below it, so the minimum occurs where half the points lie on each side: at the median.

**An example.** For $y=\{2,3,4,5,100\}$ the mean is $22.8$, dragged far away by the outlier, while the median is $4$. For $\{1,2,3,10\}$ the mean is $4$ and any $c\in[2,3]$ minimises the absolute loss; changing $10$ to $1000$ moves the mean to $251.5$ but leaves the median where it was. This is exactly what "suited for noisy data" means.
:::

:::remember
The 0/1 loss counts mistakes (good for reporting, poor for training); the squared loss punishes large errors quadratically and is smooth; the absolute loss grows linearly and resists outliers — the mean versus the median.
:::

## 3. Learning, overfitting and the train/test split

:::figs
l04-p12|The train–test split
:::


:::background what 'arg min' means
**min versus arg min.** For the function $f(c)=(c-3)^2+1$:

- $\min_c f(c)=1$ is the **smallest value** of the function;
- $\arg\min_c f(c)=3$ is the **input that achieves it**.

In learning we want the **arg min** — the actual model $h^\ast$ — not just the value of its loss.

**Overfitting in one sentence.** A model that has memorised the training answers can score perfectly on those answers while having learned nothing that transfers to new questions — exactly like memorising a past paper instead of learning the subject. The only way to detect it is to test on examples the model has **not** seen.
:::


**Learning is an optimisation problem.** Once $\mathcal H$ and $\mathcal L$ are fixed, we look for
$$
h^\ast=\arg\min_{h\in\mathcal H}\mathcal L(h).
$$
(The slides write "min", but what we want is the minimiser itself.) This finds an $h$ with low loss **on our data**. The real question, highlighted on the slides, is different: **how can we make sure that $h$ also has low loss on inputs that are not in $D$?**

:::def The memoriser
$$
h(x)=\begin{cases}y_i, &\text{if } x=x_i \text{ for some } (x_i,y_i)\in D,\\[2pt] 0, &\text{otherwise.}\end{cases}
$$
This model has zero loss on the training data, since it fits every point, yet it has large error on any input outside $D$ — like a student who memorised last year's paper. It is our **first glimpse of overfitting**.
:::

**The remedy: a train/test split.** Divide $D$ into a training set $D_{TR}$ (typically $70$, $80$ or $90\%$ of the data) and a test set $D_{TE}$ (the remaining $30$, $20$ or $10\%$). Learn using the training set only, and report the error on the test set:
$$
h^\ast=\arg\min_{h\in\mathcal H}\ \frac{1}{|D_{TR}|}\sum_{(x,y)\in D_{TR}}\mathcal L(x,y\mid h),
\qquad
\epsilon_{TE}=\frac{1}{|D_{TE}|}\sum_{(x,y)\in D_{TE}}\mathcal L(x,y\mid h^\ast).
$$

**How to split.** The split must capture the variation in the distribution: use **i.i.d. (random) sampling** for ordinary data, and for **time series split by time**, training on the past and testing on the future.

:::warn The test set is a sealed envelope
**You may use the test set only once, after the model has been decided using the training data.** Looking at the test error, adjusting the model and looking again turns the test set into training data and makes the reported error optimistic. For the same reason, normalisation statistics must be computed on the training set only.
:::

**The validation set.** Often $D$ is split three ways, for example $80\%$ training, $10\%$ validation and $10\%$ test. The validation data evaluate the loss of an $h$ learned from the training data; if the validation loss is high, we change the model and try again.

| Set | Used for (Ripley, 1996) | Analogy |
|---|---|---|
| **training** | learning: fitting the **parameters** of the model | textbook exercises |
| **validation** | tuning the **hyper-parameters** (number of hidden units, polynomial degree, $k$) | mock exams |
| **test** | assessing the performance of the **fully specified** model, once | the final exam |

:::def $K$-fold cross-validation
Divide the training data into $K$ folds (usually $5$ or $10$). For $j=1,\dots,K$, train on the other $K-1$ folds and compute the validation loss $\ell_j$ on fold $j$. The cross-validation loss is
$$
\ell_{\mathrm{CV}}=\frac1K\sum_{j=1}^K\ell_j .
$$
Every example is used for validation exactly once, and the test set remains sealed. With scarce data this is far more reliable than a single, noisy validation slice.
:::

:::example Which set is being used, and is the use legitimate? (revision notes)
1. Choosing between $k=3$ and $k=7$: the validation set or cross-validation — legitimate.
2. Computing the weights of a neural network by gradient descent: the training set — legitimate.
3. Reporting "our model is $91\%$ accurate": the test set — legitimate, provided it was opened once.
4. Seeing a low test accuracy, adding features and re-testing on the same test set: **not** legitimate, because the test set has been used for model selection.
:::

:::remember
The training set fits the parameters, the validation set tunes the hyper-parameters, and the test set is opened once; zero training error — the memoriser — proves nothing.
:::

## 5. k-Nearest Neighbours (kNN)

:::figs
l04-p18|The idea: label the query like its neighbours
l04-p20|1-NN and k-NN
:::


:::background distances, majority votes and Big-O notation
**Distance between two feature vectors** is the Euclidean distance from L01: subtract, square, add, square-root. For $(1,2)$ and $(4,6)$:
$$
\sqrt{(4-1)^2+(6-2)^2}=\sqrt{9+16}=5 .
$$
**Squared distance** skips the final square root. It is enough for kNN, because if $a<b$ then $\sqrt a<\sqrt b$ — the *order* of the neighbours does not change.

**Majority vote.** Among the $k$ neighbours, count how many belong to each class and pick the most common. With labels red, red, blue the vote is red.

**Big-O notation** describes how the work grows with the data size. "$O(dn)$" means "roughly proportional to $d\times n$": double the number of training points $n$ and the work doubles; double the number of features $d$ and it doubles too. The exact constant is ignored.

**Min–max scaling, step by step.** For a feature whose training values range from $20$ to $65$, the value $25$ becomes
$$
\frac{25-20}{65-20}=\frac{5}{45}\approx0.11 .
$$
The smallest value maps to $0$ and the largest to $1$.
:::


**The idea:** similar features have similar labels. In the slide's picture with two classes and two features, a query point surrounded by red points should be labelled red. The algorithm is: given a new test point $x$, find the **most similar** points in the training data, and classify $x$ "like" them.

The slides raise three questions: how to **measure similarity** (the distance metric), **how many** neighbours to use (the value of $k$), and how to **resolve disagreement** among the neighbours (majority voting and tie rules).

**1-NN**, the simplest classifier in machine learning, uses the label of the single closest known point. The generalisation takes the $k$ nearest neighbours and assigns their most frequent label. In the slide's picture the same query is labelled red with $k=3$ but blue with $k=7$: **the answer can change with $k$**.

:::def kNN, formally
Let $D=\{(x_1,y_1),\dots,(x_n,y_n)\}$ with labels $y_i\in\{1,\dots,M\}$. For a **query point** $x$, the **neighbour set** $S_x\subseteq D$ contains the $k$ training points closest to $x$, and
$$
h(x)=\operatorname{mode}\{\,y_i:(x_i,y_i)\in S_x\,\},
$$
the majority label among the neighbours. For **regression**, we average the neighbours' labels instead, either plainly or with weights inversely proportional to distance:
$$
h(x)=\frac1k\sum_{(x_i,y_i)\in S_x}y_i,
\qquad
h(x)=\frac{\sum_{S_x}y_i/\operatorname{dist}(x,x_i)}{\sum_{S_x}1/\operatorname{dist}(x,x_i)} .
$$
:::

**Characteristics of kNN.**

- It is **instance-based ("lazy") learning**: no model is built during training; the training data are simply **stored**.
- It is **flexible**: it adapts to unseen data by computing distances when a prediction is needed, and it can draw very irregular class boundaries.
- It makes **no assumptions** about the distribution of the data.
- It is **non-parametric**: no parameters are learned.
- Its **hyper-parameters** are $k$ and the distance metric.
- The **time and storage** needed for prediction grow with the size of the training set.

### Practical issues (slides p25–27)

- **Use an odd $k$ for binary classification**, so that a two-class vote can never be tied. (With three classes an odd $k$ does *not* prevent ties: $k=3$ can produce a $1$–$1$–$1$ vote.)
- **Ties** are resolved using prior information (for example, choosing the more common class), or by falling back to the **1-NN** or **$(k-1)$-NN** classifier.
- **Missing values** are replaced by the **average value of that feature**, computed on the training data.
- **Categorical features** are compared with the **Hamming distance**, which counts mismatches:
$$
\operatorname{dist}(x,x')=\sum_{i=1}^d\big(1-\delta_{\,x_i-x'_i}\big)=\#\{\,i:x_i\neq x'_i\,\}.
$$
For example, $(A+,\ \text{smoker},\ \text{male},\ \text{urban})$ and $(O+,\ \text{smoker},\ \text{female},\ \text{urban})$ differ in two positions, so their distance is $2$. Coding cities as $1,2,3$ and using Euclidean distance would invent a geometry that does not exist.
- **Numerical features** are usually compared with a Minkowski distance,
$$
\operatorname{dist}_p(x,x')=\Big(\sum_{j=1}^d|x_j-x'_j|^p\Big)^{1/p},
$$
with $p=2$ (Euclidean, the default), $p=1$ (Manhattan) or $p\to\infty$ (Chebyshev). Different metrics give differently shaped neighbourhoods — a diamond, a circle, a square — and can select different neighbours.
- **Mismatched scales.** A distance compresses $d$ dimensions into one number, so the features should have values of comparable size. The cure is **normalisation**, either min–max scaling or the z-score,
$$
x_j\mapsto\frac{x_j-\min_j}{\max_j-\min_j}\in[0,1],
\qquad
x_j\mapsto\frac{x_j-\mu_j}{\sigma_j},
$$
with the statistics computed on the training set.

:::example Scaling changes the prediction (2026 Quiz 5, Question 2)
:::orig [2026 Quiz 5 · Question 2 (4 marks) ↗](pdfs/quizzes/Quiz-5-Solution.pdf#page=1)
You are building a **1-NN** classifier to predict whether a patient is Low Risk or High Risk from three features: age, white-blood-cell count and number of previous visits.
Training data: $P_1=(20,5000,0)\to$ Low Risk; $P_2=(65,9500,4)\to$ High Risk. Test patient: $T=(25,9500,1)$.

(a) Calculate the squared Euclidean distance from $T$ to $P_1$ and $P_2$. What is the prediction?
(b) Larger numeric ranges can skew distances. Apply min–max scaling, $x_{\text{scaled}}=\dfrac{x-x_{\min}}{x_{\max}-x_{\min}}$, write the new coordinates of $P_1$, $P_2$, $T$, and recompute the squared distances. What is the prediction now?
(c) If the dataset grows to 1000 patients and you use 50-NN instead of 1-NN, does the variance increase or decrease? The bias? Briefly explain.
:::
The training patients are $P_1=(20,\,5000,\,0)$, labelled Low risk, and $P_2=(65,\,9500,\,4)$, labelled High risk, with features age, white-cell count and previous visits. The test patient is $T=(25,\,9500,\,1)$.

**(a) Raw features.** The squared Euclidean distances are
$$
\begin{aligned}
d^2(T,P_1)&=(25-20)^2+(9500-5000)^2+(1-0)^2=25+20\,250\,000+1=20\,250\,026,\\
d^2(T,P_2)&=(25-65)^2+(9500-9500)^2+(1-4)^2=1600+0+9=1609 .
\end{aligned}
$$
The nearest neighbour is $P_2$, so 1-NN predicts **High risk** — the white-cell count dominates.

**(b) Min–max scaling.** The ranges are $45$ (age), $4500$ (white cells) and $4$ (visits), so $P_1=(0,0,0)$, $P_2=(1,1,1)$ and $T=(0.11,\,1,\,0.25)$. Now
$$
\begin{aligned}
d^2(T,P_1)&=0.11^2+1^2+0.25^2=0.0121+1+0.0625=1.0746,\\
d^2(T,P_2)&=0.89^2+0^2+0.75^2=0.7921+0+0.5625=1.3546 ,
\end{aligned}
$$
and the prediction becomes **Low risk**.

**(c) 50-NN on 1000 patients.** Averaging over more neighbours makes the boundary smoother, so the **variance decreases**; the stronger smoothing assumption misses fine local structure, so the **bias increases**.

The revision notes make the same point with age and income in rupees: on raw values a 60-year-old appears closer to a 25-year-old than a 26-year-old does, while after z-scoring the 26-year-old is correctly the nearest.
:::

### Choice of $k$

- With $k=1$ the classifier is **sensitive to noise and has high variance**: a single mislabelled point carves out its own island. **Increasing $k$ makes the algorithm less sensitive to noise.**
- With $k=n$ every query has the same neighbours — all the points — so the classifier always predicts the overall majority class: maximally stable, but blind to the input. **Decreasing $k$ lets the model capture finer structure in the space.**
- **The idea:** choose $k$ neither too large nor too small; the right value depends on the data. **How?** Learn it from the data: split into training and validation sets (or use $5$- or $10$-fold **cross-validation**), compute the validation loss for $k=1,2,3,\dots$ using the training data to find neighbours, and choose the $k$ with the smallest validation loss. **This is the only learning that kNN requires.**
- In bias–variance terms, a small $k$ gives low bias and high variance, and a large $k$ gives high bias and low variance (2025 Mid MCQ 19; 2024 MCQ 8). A highly non-linear class boundary favours a small $k$ (PSet 4, Problem 6d).
- At $k=1$ the training error is $0$, since every point is its own nearest neighbour; this tells us nothing. Only the validation error counts.

### Algorithm, time and storage complexity (slide p32)

| Step | Cost |
|---|---|
| 1. distances from the test point to all $n$ training points in $d$ dimensions | $O(dn)$ |
| 2. find the $k$ closest: the $k$-th smallest distance by median-of-medians, then collect the points below it | $O(n)+O(n)$ |
| 3. find the most frequent label in $S_x$ | $O(k)$ |
| **time per query** | $O(dn)$ |
| **storage** (the whole training set) | $O(dn)$ |

No full sort is needed, which would cost $O(n\log n)$; a heap achieves $O(n\log k)$. For $m$ test points the cost is $O(mnd)$. On MNIST ($n=60\,000$, $d=784$) one query needs about $60\,000\times784\approx4.7\times10^7$ multiply–adds. A face-search system with $n=10^6$ embeddings of dimension $d=128$ needs about $1.3\times10^8$ operations per query and about $512$ MB of memory at $4$ bytes per number; doubling the data doubles the query time, while the training time stays essentially zero. **Most models train slowly and predict quickly; kNN trains for free and predicts expensively.** The cost depends on the size of the training set and the number of features, not on the validation set (2024 MCQ 7).

**Euclidean distance, $k=3$.** The training points are $(1,2)$A, $(2,1)$A, $(3,4)$B, $(4,3)$B and $(5,5)$B, and the test point is $(2,3)$. The distances are
$$
\sqrt2,\quad 2,\quad \sqrt2,\quad 2,\quad \sqrt{13}.
$$
The three nearest, breaking ties by list order, are $(1,2)$A, $(3,4)$B and $(2,1)$A, so the prediction is **A**.

**Manhattan distance, $k=3$.** The test point $(4,4)$ is compared with $A(1,7)$R, $B(2,3)$R, $C(3,5)$B, $D(5,2)$B, $E(6,6)$B, $F(7,1)$R and $G(8,4)$R. The distances are $6,3,2,3,4,6,4$, so the neighbours are $C$ (blue), $B$ (red) and $D$ (blue), and the prediction is **blue**.

**PSet 4, Problem 6.** For the test point $(0,0,0)$ the distances to the six observations are $3,\ 2,\ \sqrt{10},\ \sqrt5,\ \sqrt2,\ \sqrt3$. With $k=1$ the nearest is observation 5, so the prediction is **green**; with $k=3$ the neighbours are observations 5 (green), 6 (red) and 2 (red), so the prediction is **red**.
:::

:::remember
kNN stores the data and lets the $k$ closest points vote: normalise the features first, choose $k$ by cross-validation (a small $k$ means high variance, a large $k$ high bias), and expect to pay $O(dn)$ per prediction.
:::

## 6. Curse of dimensionality (Worksheet 2, P3; outline)

:::background powers of a small number
**Multiplying fractions shrinks things fast.** If a window catches $10\%$ of the data along one feature, then requiring it along two independent features catches $10\%$ of $10\%$, which is $1\%$:
$$
0.1\times0.1=0.01,\qquad 0.1^3=0.001,\qquad 0.1^{10}=0.000\,000\,000\,1 .
$$
**Roots go the other way.** To catch $10\%$ in total with $p$ features, each side must catch a fraction $L$ with $L^p=0.1$, so $L=0.1^{1/p}$. As $p$ grows, $1/p$ shrinks towards $0$, and $0.1^{1/p}$ creeps up towards $1$ — the window must cover nearly the whole range of every feature.
:::

Suppose each of $p$ independent features is uniform on $[0,1]$, and kNN uses only those training points within $0.05$ of the test point in **every** feature — a cube of side $0.1$. The fraction of the training data inside that cube is $0.1^p$:

| Number of features $p$ | Fraction of data in the neighbourhood |
|---|---|
| $1$ | $0.1=10\%$ |
| $2$ | $0.1^2=1\%$ |
| $100$ | $0.1^{100}=10^{-100}$ — essentially nothing |

Reversing the question, a cube that captures $10\%$ of the data must have side $L$ with $L^p=0.1$, that is,
$$
L=0.1^{1/p}:\qquad L=0.1\ (p=1),\qquad L\approx0.316\ (p=2),\qquad L\approx0.977\ (p=100).
$$
In a hundred dimensions the "neighbourhood" spans almost the whole range of every feature. The nearest neighbours are no longer near, so kNN's founding assumption — similar inputs have similar labels — breaks down. This motivates dimensionality reduction (PCA, after the mid).

:::remember
In high dimensions the volume near any point is exponentially small, so nearest neighbours stop being similar.
:::

## 7. Evaluating a classifier: accuracy and its trap

The 0/1 loss averaged over the test set is the **misclassification rate**, an estimate of the probability that a point is classified incorrectly; for each test point the loss is either $0$ or $1$. Its complement is the accuracy:
$$
\text{accuracy}=1-\text{misclassification rate}.
$$
**The issue: accuracy is not meaningful when the classes are imbalanced or skewed.**

:::example The no-ball example
We predict whether a bowler will **not** bowl a no-ball. Suppose an innings of $315$ deliveries contains $15$ no-balls, so the no-ball class (class $0$) is $4.76\%$ of the data and legal balls (class $1$) are $95.24\%$. A model that answers "yes, legal" **every time** achieves
$$
\text{accuracy}=\frac{300}{315}\approx95\% ,
$$
which sounds excellent — yet it never catches a single no-ball, which was the whole purpose of the model. The classes are **imbalanced**.
:::

## 8. TP, TN, FP, FN and the confusion matrix

:::figs
l04-p40|The confusion matrix
l04-p41|Heart-disease example
l04-p42|No-ball example
:::


:::background reading the four counts
Every prediction falls into exactly one of four boxes, decided by two yes/no questions: **what did the model say?** and **was it right?**

| | the truth is **positive** | the truth is **negative** |
|---|---|---|
| the model says **positive** | true positive (correct alarm) | false positive (false alarm) |
| the model says **negative** | false negative (a miss) | true negative (correct all-clear) |

**A sanity check** that saves marks: the four counts must add up to the total number of test cases, each **column** adds up to the number of actual positives or negatives, and each **row** adds up to the number of predicted positives or negatives.
:::


Consider a binary problem with $\mathcal Y=\{0,1\}$, where $0$ is called negative and $1$ positive. The true labels $y$ are the **ground truth** (also called gold labels or the gold standard), and the classifier outputs $h(x)=\hat y$. A prediction is called "true" if $\hat y=y$ and "false" if $\hat y\neq y$.

| Count | Truth $y$ | Prediction $\hat y$ |
|---|---|---|
| **TP**, true positive | $1$ | $1$ |
| **TN**, true negative | $0$ | $0$ |
| **FP**, false positive (a false alarm) | $0$ | $1$ |
| **FN**, false negative (a miss) | $1$ | $0$ |

**A decoding trick:** the second word says what the model **predicted**, and the first word says whether it was **right**. A "false negative" is a negative prediction that was wrong — a sick patient sent home.

:::def Confusion matrix (the layout on the slides)
The four counts are arranged in a table whose **rows are predicted classes** and whose **columns are true classes**:

| | Actual 1 (positive) | Actual 0 (negative) | Total |
|---|---|---|---|
| **Predicted 1** | TP | FP | predicted positives |
| **Predicted 0** | FN | TN | predicted negatives |
| **Total** | $P=TP+FN$, actual positives | $N=FP+TN$, actual negatives | |

The diagonal holds the correct predictions and the off-diagonal holds the mistakes. (The slide prints "N = P + TN"; it should read $N=FP+TN$.) **Many textbooks, and scikit-learn, transpose this table**, putting the truth on the rows, so always check the axis labels; Worksheet 2 uses the transposed layout.
:::

**The slide's two examples.**

| Heart disease (1 = disease) | $y=1$ | $y=0$ | Total |
|---|---|---|---|
| $\hat y=1$ | TP $=100$ | FP $=10$ | $110$ |
| $\hat y=0$ | FN $=5$ | TN $=50$ | $55$ |
| Total | $P=105$ | $N=60$ | $165$ |

Out of $165$ cases the model said "yes" $110$ times and "no" $55$ times; in reality the answer was "yes" $105$ times and "no" $60$ times.

| No-ball (1 = legal ball) | $y=1$ | $y=0$ | Total |
|---|---|---|---|
| $\hat y=1$ | TP $=298$ | FP $=7$ | $305$ |
| $\hat y=0$ | FN $=2$ | TN $=8$ | $10$ |
| Total | $P=300$ | $N=15$ | $315$ |

This model, trained on fifteen years of bowling records, predicted $305$ legal balls and $10$ no-balls, of which $8$ were correct and $2$ incorrect. It missed $7$ genuine no-balls, which appear as FP because "positive" here means a legal ball.

:::remember
Rows are what the model said and columns are the truth; $P=TP+FN$ and $N=FP+TN$ are the column totals.
:::

## 9. Metrics from the confusion matrix

:::figs
l04-p45|Metric definitions
:::


:::background fractions 'out of' a group
Every metric is a fraction **out of one group** of cases. The trick is knowing which group goes in the denominator.

- **Recall** $=\dfrac{TP}{TP+FN}$: out of the people who are **actually sick**, what fraction did we catch?
- **Specificity** $=\dfrac{TN}{TN+FP}$: out of the people who are **actually healthy**, what fraction did we clear?
- **Precision** $=\dfrac{TP}{TP+FP}$: out of the people we **said** were sick, what fraction really were?

**Example.** 100 sick and 900 healthy people; the test flags 90 of the sick and 45 of the healthy. Then
$$
\text{recall}=\frac{90}{100}=90\%,\qquad \text{specificity}=\frac{855}{900}=95\%,\qquad \text{precision}=\frac{90}{90+45}\approx67\% .
$$
The same test looks excellent or mediocre depending on which question you ask.
:::


Every metric is the fraction of **one row or one column** of the confusion matrix. Column metrics condition on the truth; row metrics condition on the prediction.

| Metric | Formula | The question it answers |
|---|---|---|
| **accuracy** | $\dfrac{TP+TN}{P+N}$ | Overall, how often is the classifier correct? |
| **error rate** | $1-\text{accuracy}=\dfrac{FP+FN}{P+N}$ | Overall, how often is it wrong? |
| **sensitivity, recall, TPR** $S_e$ | $\dfrac{TP}{TP+FN}=\dfrac{TP}{P}$ | When the truth is positive, how often does it predict positive? |
| **specificity, TNR** $S_p$ | $\dfrac{TN}{TN+FP}=\dfrac{TN}{N}=1-\text{FPR}$ | When the truth is negative, how often does it predict negative? |
| **false positive rate** | $\dfrac{FP}{TN+FP}=\dfrac{FP}{N}$ | When the truth is negative, how often does it predict positive? |
| **precision** | $\dfrac{TP}{TP+FP}$ | When it predicts positive, how often is it right? |
| **negative predictive value** | $\dfrac{TN}{TN+FN}$ | When it predicts negative, how often is it right? |

:::example The heart-disease numbers (slides p46–47)
$$
\begin{aligned}
\text{accuracy}&=\frac{100+50}{165}=0.91, & \text{error rate}&=\frac{10+5}{165}=0.09,\\[2pt]
\text{sensitivity}&=\frac{100}{105}=0.95, & \text{FPR}&=\frac{10}{60}=0.17,\\[2pt]
\text{specificity}&=\frac{50}{60}=0.83, & \text{precision}&=\frac{100}{110}=0.91,\\[2pt]
\text{NPV}&=\frac{50}{55}=0.91 .
\end{aligned}
$$
For the no-ball model, accuracy is $306/315=0.971$, sensitivity $298/300=0.993$ and precision $298/305=0.977$, but the **specificity** is only $8/15=0.533$. That single number exposes the problem: barely half of the no-balls are caught.
:::

The revision notes offer an analogy: recall is the fraction of all the fish in the lake that ended up in your net, and precision is the fraction of what is in your net that is actually fish. A net that scoops up the whole lake has perfect recall and terrible precision.

:::warn Precision depends on prevalence; sensitivity and specificity do not
**PSet 4, Problem 8.** A screening test on $2030$ people gives TP $=20$, FP $=180$, FN $=10$ and TN $=1820$. Then
$$
\text{sensitivity}=\frac{20}{30}=0.667,\quad \text{specificity}=\frac{1820}{2000}=0.91,\quad \text{FPR}=0.09,\quad \text{precision}=\frac{20}{200}=0.10,\quad \text{NPV}=\frac{1820}{1830}=0.995,\quad \text{accuracy}=\frac{1840}{2030}=0.906 .
$$
Only $30$ people have the condition (a prevalence of about $1.5\%$), so a $9\%$ false-positive rate applied to $2000$ healthy people produces $180$ false alarms, which swamp the $20$ true positives. The test is still useful for screening, because a negative result is almost always correct.

**2026 Quiz 5, Question 3.** There are $10\,000$ patients and the prevalence is $1\%$, so $P=100$ and $N=9900$. A recall of $100\%$ means TP $=100$ and FN $=0$. A precision of $10\%$ means
$$
\frac{100}{100+FP}=0.10\quad\Longrightarrow\quad FP=900,\qquad\text{and therefore}\qquad TN=9900-900=9000 .
$$
The accuracy is $9100/10\,000=91\%$ and the false-positive rate is $900/9900=1/11\approx9.09\%$. The model's flaw is the $900$ healthy people given a false alarm. An ROC curve would **not** expose it, because the huge number of true negatives keeps the false-positive rate low; precision is the metric that reveals it.
:::

:::remember
Recall $=TP/P$ (did we catch the positives?), specificity $=TN/N$, FPR $=FP/N$, precision $=TP/(TP+FP)$ (can we trust a positive?), and NPV $=TN/(TN+FN)$.
:::

## 10. When to use which metric; trade-offs

:::figs
l04-p50|Precision–recall trade-off
:::



**Decide which mistake is more expensive, then watch the metric that punishes it** (slide p48).

- **Disease detection — we do not want false negatives.** Sending a sick patient home can be fatal, while a false alarm costs only a follow-up test, so we watch the **sensitivity** $TP/(TP+FN)$. For a cancer classifier (2024 and 2025 Mid MCQs) we prefer $FP\gg FN$.
- **Fraud detection — we do not want false positives.** Every false positive blocks an honest customer, so we watch the **specificity** $TN/(TN+FP)$ and the **precision** $TP/(TP+FP)$. A spam filter is similar: prioritise specificity (2025 Quiz 3).

**The precision–recall trade-off** (slide p50). Recall measures how well we detect diseased people; precision measures how many of those diagnosed as diseased really are. If we diagnose **everyone** as unhealthy, then $S_e=1$, but the precision may be low, because $TN=0$ inflates the false positives; for the heart data it falls to $P/(P+N)=105/165=0.64$. We want both quantities to be high, ideally $1$, so we combine them into a single score — the $F_1$ score.

**The sensitivity–specificity trade-off** (slide p51). $S_p$ and $S_e$ measure how well we detect healthy and diseased people respectively. If we diagnose **everyone** as healthy, then $S_p=1$ but $S_e=0$. Ideally $S_p=S_e=1$, but that is unrealistic.

**The threshold slider.** Most classifiers produce a score that is compared with a threshold. Because the scores of healthy and sick people overlap, lowering the threshold catches more sick people (sensitivity rises) at the cost of more false alarms (specificity falls), and raising it does the opposite.

:::example Interpreting recall correctly (2024 Mid, MCQ 11)
:::orig [2024 Mid Part I · MCQ 11 ↗](pdfs/past/Mid-2024-Part1.pdf#page=2)
For a binary classifier that predicts whether a customer will pay back a loan, the recall is $83\%$. Determine the correct implication of using this classifier. *(Select all, up to three.)*

(a) We can interpret that $83\%$ of all the customers will pay back.
(b) $17\%$ of the customers who could have paid back the loan will have their application rejected.
(c) $83\%$ of the customers who could have paid back the loan will have their application rejected.
(d) We can interpret that $17\%$ of all the customers will pay back the loan.
:::
**Answer: (b) only.** Recall $=\dfrac{TP}{TP+FN}=\dfrac{TP}{P}$ is measured *only among the customers who really would repay* ($P$). So of those customers, $83\%$ are approved (TP) and **$17\%$ are wrongly rejected** (FN) — that is (b). (c) swaps the two percentages, and (a) and (d) talk about "all customers", which recall says nothing about.
:::

## 11. ROC curve and AUC

:::figs
l04-p52|ROC curve and AUC
:::


:::background thresholds and areas
**A threshold.** Many classifiers output a *score*, say a number between $0$ and $1$ for "how likely is this patient sick". We then choose a cut-off $t$: scores at or above $t$ are called positive.

- A **low** threshold calls almost everyone positive: few misses, many false alarms.
- A **high** threshold calls almost everyone negative: few false alarms, many misses.

**The ROC curve** shows every choice at once: for each threshold, plot (false-alarm rate, catch rate). Moving the threshold traces a curve from $(0,0)$ (nobody flagged) to $(1,1)$ (everybody flagged).

**Area under a curve.** The AUC is the area of the region beneath that curve inside the unit square. A perfect classifier hugs the top-left corner, giving the whole square, area $1$; random guessing follows the diagonal, area $\tfrac12$.
:::


:::def The ROC curve
Move the threshold from strict to lenient and, at each value, plot the point
$$
(\text{FPR},\ \text{TPR})=\big(1-S_p,\ S_e\big).
$$
- The **TPR** (sensitivity) is the fraction of positive samples that are correctly identified.
- The **FPR** ($1-$ specificity) is the fraction of negative samples that are incorrectly flagged.
- The **best possible classifier** has $S_e=S_p=1$, the **upper-left corner** $(0,1)$.
- A **random guess** lies on the **diagonal**, the line of no discrimination: it has no power.
- The **area under the curve (AUC)** quantifies the power of the classifier: $1$ is perfect and $0.5$ is random. The "alarmist" who calls everyone sick sits at $(1,1)$ and the "optimist" who calls everyone healthy at $(0,0)$.
:::

**What AUC really means** (beyond the slides). It is the probability that a randomly chosen positive receives a **higher score** than a randomly chosen negative — a measure of ranking quality that does not depend on any single threshold. A curve lying below the diagonal, with AUC $0.2$, is reliably wrong rather than useless: inverting its predictions gives AUC $0.8$.

:::example ROC points and AUC by hand (PSet 4, Problem 10)
:::orig [PSet 4 · Problem 10 ↗](pdfs/psets/PSet-04.pdf#page=2) · [solution](pdfs/psets/PSet-04-Solution.pdf)
Twenty test instances are sorted by classifier score ($p$ = actually positive, $n$ = actually negative):

| score | 0.9 | 0.8 | 0.7 | 0.6 | 0.55 | 0.54 | 0.53 | 0.52 | 0.51 | 0.505 |
|---|---|---|---|---|---|---|---|---|---|---|
| label | p | p | n | p | p | p | n | n | p | n |
| **score** | **0.4** | **0.39** | **0.38** | **0.37** | **0.36** | **0.35** | **0.34** | **0.33** | **0.30** | **0.1** |
| label | p | n | p | n | n | n | p | n | p | n |

(a) An instance is predicted positive if its score is at least $t$. Give the (FPR, TPR) point for $t=0.54$, $0.51$ and $0.38$. (b) Compute the accuracy at $t=0.54$. (c) Compute the AUC as the probability that a random positive is scored higher than a random negative. (d) Where do the perfect and the random classifier lie in ROC space?
:::
Twenty instances, ten positive and ten negative, are sorted by score from $0.9$ down to $0.1$, with labels

p p n p p p n n p n &nbsp;|&nbsp; p n p n n n p n p n.

1. At threshold $t=0.54$ the classifier flags the top six instances, giving TP $=5$ and FP $=1$, so the ROC point is $(0.1,\,0.5)$; the accuracy is $(5+9)/20=0.70$.
2. At $t=0.51$: TP $=6$, FP $=3$, giving $(0.3,\,0.6)$. At $t=0.38$: TP $=8$, FP $=5$, giving $(0.5,\,0.8)$.

The ROC curve plots TPR against FPR over all thresholds: the top-left corner is perfect, the diagonal is random, and the AUC is the probability that a random positive outranks a random negative.
:::

## 12. F-scores and Matthews correlation coefficient

:::figs
l04-p56|Why the harmonic mean: min ≤ HM ≤ GM ≤ AM ≤ max
:::


:::background the harmonic mean
**The arithmetic mean** of $a$ and $b$ is $\tfrac{a+b}{2}$. **The harmonic mean** is
$$
\text{HM}=\frac{2}{\frac1a+\frac1b}=\frac{2ab}{a+b}.
$$
It is the right average for **rates**. Drive 60 km at 30 km/h (2 hours) and 60 km back at 60 km/h (1 hour): 120 km in 3 hours is 40 km/h, which is the harmonic mean of 30 and 60 — not 45.

**Why it punishes imbalance.** With $a=1$ and $b=0.02$, the arithmetic mean is $0.51$ but the harmonic mean is $\tfrac{2(0.02)}{1.02}\approx0.039$. The harmonic mean is dragged down to the smaller of the two.
:::


Higher recall can usually be bought at the price of lower precision, so we need a single measure that combines the two. The slides list several: the **$F_1$ score**, the **Matthews correlation coefficient**, the 11-point average precision and the breakeven point.

:::def F-scores: a weighted harmonic mean
$$
F_\beta=\frac{1+\beta^2}{\dfrac{1}{\text{Precision}}+\dfrac{\beta^2}{\text{Recall}}},\qquad\beta\ge0 .
$$
For $\beta=1$ this is the plain harmonic mean,
$$
F_1=\frac{2}{\dfrac{1}{\text{Precision}}+\dfrac{1}{\text{Recall}}}=\frac{2\cdot\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}}=\frac{2\,TP}{2\,TP+FP+FN}.
$$
A value $\beta>1$ weights recall more heavily (for example $F_2$ in disease screening), and $\beta<1$ weights precision more heavily ($F_{0.5}$ for fraud flags). For the heart data, $F_1=200/215=0.93$, $F_2=0.94$ and $F_{0.5}=0.92$.
:::

**Why the harmonic mean?** We could use the arithmetic mean (AM) or the geometric mean (GM), but the harmonic mean (HM) **penalises an unbalanced model the most**; it is a conservative average. For two positive numbers,
$$
\min\le\text{HM}\le\text{GM}\le\text{AM}\le\max ,
$$
and an improvement in HM implies an improvement in AM or GM. The slide's plot fixes recall at $70\%$: the HM hugs the minimum, so at a precision of $5\%$ the AM still reports $37.5\%$ while $F_1$ honestly reports $9.3\%$. The revision notes' analogy is a round trip of $60$ km driven out at $30$ km/h and back at $60$ km/h: the average speed is $120\text{ km}/3\text{ h}=40$ km/h, the harmonic mean, and not $45$.

:::example The harmonic mean tells the truth
:::orig [Worksheet 2 · Problem 2 ↗](pdfs/psets/Worksheet-02.pdf#page=1)
*(The fraud example in the first paragraph is from the lecture slides; the worksheet question is below.)*
The confusion matrix of a classifier that detects the digit 5 on 60 000 MNIST images is
$$\begin{pmatrix}53\,892&687\\1891&3530\end{pmatrix},$$
with **rows = actual class** and **columns = predicted class**, both in the order (not-5, 5) — the transpose of the lecture's layout.
(a) Identify TP, FP, FN and TN. (b) Compute precision, recall and $F_1$. (c) Compute the arithmetic mean (AM) and geometric mean (GM) of precision and recall; verify HM $\le$ GM $\le$ AM and explain why $F_1$ uses the harmonic mean. (d) A colleague says: "This model has about 96% accuracy, so it is an excellent 5-detector." Compute the model's accuracy and that of a classifier that always predicts "not 5", and explain what is wrong with the colleague's reasoning.
:::
A fraud model flags a single transaction, correctly, while $50$ frauds exist. Its precision is $1$ and its recall is $0.02$. The arithmetic mean is $0.51$, which is misleading, whereas
$$
F_1=\frac{2\,(1)(0.02)}{1+0.02}\approx0.039 .
$$
**Worksheet 2** (an MNIST "5"-detector, truth on the rows): TN $=53\,892$, FP $=687$, FN $=1891$, TP $=3530$. Then
$$
\text{precision}=\frac{3530}{4217}=0.837,\qquad \text{recall}=\frac{3530}{5421}=0.651,\qquad F_1=\frac{7060}{9638}=0.733,
$$
while AM $=0.744$ and GM $=0.738$, confirming $\text{HM}\le\text{GM}\le\text{AM}$. The accuracy is $57\,422/60\,000=0.957$, yet a classifier that always says "not 5" scores $54\,579/60\,000=0.910$: accuracy is dominated by the easy majority class.
:::

:::def Matthews correlation coefficient
$$
\text{MCC}=\frac{TP\cdot TN-FP\cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}\in[-1,1].
$$
Unlike $F_1$, which ignores TN entirely, MCC uses **all four cells**. It is the correlation coefficient of L01 between the vector of true labels and the vector of predicted labels: $+1$ means perfect prediction, $0$ means chance level and $-1$ means perfectly wrong. (If a factor in the denominator is zero, MCC is defined to be $0$.)
:::

| Model | Accuracy | $F_1$ (class 1 positive) | MCC |
|---|---|---|---|
| heart disease | $0.91$ | $0.93$ | $0.80$ |
| cricket model | $0.97$ | $0.99$ | $0.64$ |
| cricket "always yes" | $0.95$ | $0.98$ | $0$ |

In PSet 4, Problem 9, a dataset with $91$ positives and $9$ negatives gives TP $=90$, FN $=1$, TN $=0$, FP $=9$. Then the accuracy is $0.90$ and $F_1=180/190=0.95$, but
$$
\text{MCC}=\frac{90\cdot0-9\cdot1}{\sqrt{99\cdot91\cdot9\cdot1}}\approx-0.03 ,
$$
and only MCC tells the truth: the model never identifies a negative. For the heart data,
$$
\text{MCC}=\frac{100\cdot50-10\cdot5}{\sqrt{110\cdot105\cdot60\cdot55}}=\frac{4950}{6173.7}\approx0.80 .
$$

**$F_1$ depends on which class is called positive.** Making the no-ball the positive class gives TP $=8$, FN $=7$, FP $=2$ and TN $=298$, so $F_1=16/25=0.64$ instead of $0.985$, while MCC is unchanged, because its formula is symmetric under exchanging the classes. On imbalanced data, make the rare and important class the positive one, or report MCC.

:::derive why $F_1=\dfrac{2TP}{2TP+FP+FN}$
Start from the harmonic mean of precision $P=\tfrac{TP}{TP+FP}$ and recall $R=\tfrac{TP}{TP+FN}$:
$$
F_1=\frac{2}{\frac1P+\frac1R}=\frac{2}{\frac{TP+FP}{TP}+\frac{TP+FN}{TP}}=\frac{2}{\frac{2TP+FP+FN}{TP}}=\frac{2TP}{2TP+FP+FN}.
$$
The step in the middle adds two fractions with the same denominator $TP$. **Check** with the heart data, TP $=100$, FP $=10$, FN $=5$: $\tfrac{200}{200+10+5}=\tfrac{200}{215}\approx0.93$.
:::

:::remember
$F_1=2TP/(2TP+FP+FN)$ is the harmonic mean of precision and recall and is dragged down by the worse of the two; MCC uses all four cells and is the honest single number for imbalanced data.
:::

:::remember The one line for this lecture
Learn $h=\arg\min_{h\in\mathcal H}\mathcal L$ on the training data, tune on validation data and test once; kNN classifies by a vote among the $k$ nearest (normalised) points; and a classifier is judged by the confusion-matrix metric that matches the costly mistake — never by accuracy alone when the classes are imbalanced.
:::
